# 📌 애자일(Agile) 스프린트 & 문서화 가이드

## 1. Jira 백로그 & 스프린트 운영 원칙

### 🔹 백로그 (Backlog) 관리
* **작업의 이슈화**: 기술조사, 통합테스트, 모방학습 추론기 개발 등 모든 작업은 생각날 때마다 백로그에 개별 티켓(Issue)으로 즉시 발행
* **스프린트 할당**: 백로그에 누적된 티켓을 우선순위에 맞게 드래그하여 해당 스프린트로 이동
* **이슈 작성 규칙**:
  * **담당자(Assignee)**: 명확하게 지정
  * **설명(Description)**: 작업 목적과 해야 할 일을 짧고 명확하게 기술
  * **산출물 링크 연동**: Confluence에 기술조사 및 문서를 작성한 뒤, 해당 링크를 Jira 설명에 첨부

### 🔹 스프린트 라이프사이클
* **주기**: 1주일 단위 진행
* **시작**: 매주 시작 시 **Start Sprint** 클릭
* **종료**: 주차 종료 시 **Complete Sprint** 처리
* **미완료 작업**: 기간 내 처리하지 못한 티켓은 자동으로 다음 스프린트로 이월
* **추가 작업 원칙**:
  * 스프린트 조기 종료란 없음
  * 계획된 티켓을 일찍 완료하면 백로그에서 우선순위가 높은 작업을 추가로 가져와 진행

## 2. 회의 및 협업 프로세스

### 🔹 데일리 스탠드업 (Daily Scrum)
* **시간**: 매일 아침, **10분 이내 엄수**
* **공유 내용**:
  * 어제 진행한 작업
  * 오늘 진행할 작업
  * 개인 일정(지각, 조퇴 등 부재) 및 이에 따른 대처 방안
* **운영 규칙**: 깊은 기술적 논의가 필요한 이슈 발생 시 회의를 연장하지 않고, 해당 담당자들끼리 별도 일정을 잡아 진행

### 🔹 스프린트 리뷰 & 회고 (주 1회)
* **진행 시점**: 매 스프린트 종료 시점
* **스프린트 리뷰**:
  * 전체 이슈 검토 및 담당자별 완료 업무 리뷰
  * 미완료 이슈에 대한 원인 분석(일정 산정 오류, 기술 블로커 등)
  * 차주 스프린트 백로그 선정 및 우선순위 조정
* **회고 (Retrospective)**:
  * **Keep (잘된 점)**: 효과적이었던 개발 방식, 협업 사례, 시간 관리법 등 팀 전체 공유 및 유지
  * **Problem & Action Item (아쉬운 점 & 개선안)**:
    * 감정적 불만 대신 문제의 원인과 해결책을 구체적으로 도출  
      *(예: "이슈 단위가 너무 커서 지연됨" ➔ "다음 스프린트부터 이슈 단위를 1~2일 내 완료 가능하게 세분화")*
    * 도출된 개선안은 다음 스프린트 프로세스에 즉시 반영

### 🔹 소통 원칙
* **회의 최소화**: 전체 회의는 최소화하고, 개발 몰입 시간 확보
* **비동기 소통**: 구두 전달 대신 **Jira 티켓과 Confluence 문서를 통한 소통**을 기본 원칙으로 함

## 3. 기획 및 엔지니어링 산출물 정의 (Confluence)

| 단계 | 산출물 | 영문 약칭 | 주요 작성 내용 |
| :--- | :--- | :--- | :--- |
| **요구사항** | **사용자 요구사항서** | **UR** *(User Requirements)* | 클라이언트 및 사용자 관점에서의 전체 요구사항 명세 |
| | **시스템 요구사항서** | **SR** *(System Requirements)* | UR 중 프로젝트 범위 내에서 실제 엔지니어링으로 구현할 핵심 요구사항 도출 |
| **시스템 아키텍처** | **하드웨어 아키텍처** | **H/W SA** | H/W 구성 요소 배치도, 물리적 연결도, 보드/센서 간 통신 방식 |
| | **소프트웨어 아키텍처** | **S/W SA** | 모듈/노드 구조, 입출력 데이터 흐름, 컴포넌트 간 통신 프로토콜 정의 |
| **설계 & 모델링** | **시퀀스 다이어그램** | **Sequence Diagram** | 시나리오별 객체/컴포넌트 간 메시지 호출 순서 및 시계열 처리 과정 |
| | **상태 다이어그램** | **State Diagram** | 로봇 동작 모드, 상태 전이 조건, 예외 처리(FSM) 정의 |
| | **통신 프로토콜 명세서** | **Interface Specification** | ROS Topic/Service, REST API, 소켓 패킷 등 메시지 필드 및 데이터 타입 정의 |
| | **환경/맵 지형도** | **Map/Topology** | 시뮬레이션 및 실주행 공간 지형도, 주요 좌표계(Waypoint) 및 작업 영역 시각화 |
