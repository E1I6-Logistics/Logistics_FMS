# Real mode 연결·점유·정지 정책

## 연결 상태

- Zenoh REST 조회 오류는 정상적인 빈 연결 목록과 구분한다. 조회 실패 중에는 마지막 화면 값을 유지하고 FMS 연결 상태를 변경하지 않는다.
- REST 조회가 성공했으나 로봇이 누락되면 `FMS_ZENOH_MISSING_GRACE_S`(기본 5초) 동안 기존 연결 상태를 유지한다. 유예 시간이 지난 정상 스냅샷에서도 누락되면 OFFLINE으로 바꾼다.
- 연결 상태와 Pose 최신성은 별도로 검사한다. Zenoh 연결이 유지돼도 주행 로봇의 Pose가 오래되면 해당 로봇을 정지시킬 수 있다.

## RealNavigation의 정지 범위

| 관측 상황 | 처리 |
| --- | --- |
| 예약 출발 시각 전 | WAITING. Nav2 Goal을 시작하지 않는다. |
| 시간표가 지연됐지만 현재 구간에 실제 점유·예약 충돌이 없음 | 이미 진행 중인 Goal은 시간 초과만으로 취소하지 않는다. |
| 주행 로봇의 Pose가 오래됐고 기존 경로가 확인됨 | 그 경로의 노드·통로를 보호하고 해당 로봇을 정지한다. 겹치지 않는 로봇은 계속 감시한다. |
| 실제 Pose가 예상 경로 밖이지만 그래프의 노드·통로에 대응됨 | 실제 자원과 기존 경로를 보호하고 해당 로봇을 정지한다. 겹치는 로봇의 진입도 막는다. |
| 실제 점유 충돌 또는 보호된 자원과 충돌 | 충돌 가능성이 있는 로봇의 진입/주행을 중단한다. |
| Pose를 그래프의 어느 자원에도 대응할 수 없음 | 영향 범위를 특정할 수 없으므로 기존 전체 실행 정지 정책을 유지한다. |

새로 연결된 로봇에 첫 Pose가 없을 때는 담당 충전 노드를 임시 보호한다. 기본 3초가 지나도 위치를 알 수 없으면 전체 정지 정책을 유지한다. 그 로봇이 실제로 충전 노드에 있다고 확인할 수 없기 때문이다.

## Nav2 취소와 복구

- 취소 요청과 취소 수락만으로 기존 Goal을 종료한 것으로 보지 않는다. 최종 결과를 받아야 예약과 새 명령의 안전성을 판단할 수 있다.
- 취소 중 결과 조회가 유실되면 최대 3회 결과를 재조회한다. 재조회는 종료 증거가 아니며 Goal handle과 예약을 해제하지 않는다.
- 종료 결과가 끝내 오지 않으면 PAUSED와 보호 예약을 유지한다. 로봇의 Nav2 상태를 확인하기 전에는 새 Goal이나 비상정지 해제를 자동 허용하지 않는다.
- 대시보드에 PAUSED 사유를 표시한다. `No viapoints given`과 같은 Planner 실패의 정확한 원인은 FMS Goal 개수·좌표 로그와 로봇 Nav2 로그를 같은 시각에 대조한다.
